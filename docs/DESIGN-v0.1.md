## 1. 지도·자원·시간

### 1.1 시간
- 시뮬레이션은 **틱** 단위로만 진행합니다. 1틱 = 모든 슬라임이 한 번 감지·판단·행동(순서는 9절). 세계의 `tick` = 지금까지 진행한 틱 수입니다. 틱 t 를 진행하는 동안 생긴 기록과 진행한 뒤 상태(틱 t+1)의 구분은 8.4 "틱 기준".
- 하루 `time.day_ticks`(기본 60). 빛 `light`(0~1)은 낮 구간 [0, 하루 × `time.daylight_fraction`)(기본 36틱) 안쪽 양 끝에서 `time.twilight_ticks`(기본 6)틱 동안 0 ↔ 1 로 고르게 바뀌고, 그 사이는 1, 나머지(밤)는 0 입니다(삼각함수 안 씀). 그래서 하루 빛 합 = 낮 틱 − twilight(기본 30), 빛 1 인 틱 = 낮 틱 − 2 × twilight + 1(기본 25)입니다. twilight 은 하루 × 낮 비율 ÷ 2 이하여야 합니다(검사).
- **밤**: 빛이 `time.night_light_threshold`(기본 0.5)보다 작은 틱. 밤에는 감지 반경이 × `sense.night_factor`(최소 1칸)로 줄어듭니다. 실험실 위쪽 막대의 낮/밤 표시도 그 세계의 같은 키를 읽습니다.
- 1년 = 계절 4개 × `time.season_days`(기본 2일 = 120틱). 계절 = (틱 ÷ 하루 ÷ 계절 날 수) mod 4 — 0 봄·1 여름·2 가을·3 겨울. 계절 성장 배수 `seasons.growth = [1.0, 1.2, 0.8, 0.3]`. `time.season_days = 0` 이면 계절 없음(계절 −1, 배수 1). (초안의 4일·겨울 0.1 은 겨울이 수명 한 번만큼 길어 첫 세대가 매번 멸종 → 17절. 예설정 `harsh_winter`(겨울 0·계절 5일)는 **멸종 조건**입니다: 씨앗 1~12 를 8,000틱 돌리면 모두 멸종 — 결과는 [`CONFIG.md`](CONFIG.md) 예설정 표.)
- 화면 속도 1배 = `ui.speed.ticks_per_second_1x`(기본 6틱/초). 속도 1·2·4·8·16·32·64배(`ui.speed.steps`)와 **빨리 감기**(프레임 예산 안에서 최대한).

### 1.2 지도
- 격자 `map.width × map.height`(기본 64×48), 칸 번호 c = y × 너비 + x. 칸 종류: 풀밭(비옥도 0~1)·물(지날 수 없음)·바위(지날 수 없음, 식물 없음)·밭(농사 발견 뒤 심어서 생김).
- 지형은 씨앗으로 만듭니다: 정수 해시 값 잡음(value noise) 두 겹 — 큰 무늬(`map.noise_cell`)와 잔무늬(`map.noise_detail_cell`)를 `map.noise_detail_weight` 로 섞은 지형 값이 `map.water_level` 보다 낮으면 물, 따로 된 바위 잡음(`map.rock_noise_cell`)이 `map.rock_level` 보다 크면 바위, 나머지는 풀밭(비옥도 = `map.fertility_floor` + (1 − 그 값) × 물 높이 위로 올라간 몫). 사칙연산만 씁니다.
- 잡음 씨앗은 64비트 씨앗의 아래 32비트에 위 32비트를 섞은 값입니다(`SimTerrain.terrain_seed` — 씨앗 0 ~ 2^32 − 1 은 씨앗 그대로, 2^32 차이 나는 씨앗도 다른 지도. 검토 J14).
- 생성 뒤 **연결성 정리**: 가장 큰 통과 가능 영역만 남기고 나머지 섬은 바위로 메웁니다(슬라임이 갇히지 않게, 연결 요소 계산은 칸 수에 비례 — 검토 I31). 이전 저장소의 `grid_logic.gd` BFS 에서 울타리·건물 점유 부분은 빼고 "통과 가능 칸·다중 출발 BFS 거리장"만 가져왔습니다(`SimGrid`).

### 1.3 식물(먹이)
- 풀밭 칸마다 식물 먹이 `food[c]`, 상한 = `plants.max_food × 비옥도 × resources.scale`. 시작할 때 상한 × `plants.initial_fill`(0.8).
- 성장은 `plants.update_every`(기본 2)틱마다 몰아서 합니다: 그 갱신부터 다음 갱신 전까지 **틱마다의 (빛 몫 × 계절 배수)를 더한 값** × `plants.regrow × 비옥도 × resources.scale` 만큼(상한까지). 빛 몫 = `plants.night_growth` + (1 − 그 값) × 빛(기본 night_growth 0 → 빛 그대로). 그래서 갱신 간격은 **성능용**이고 자라는 양은 간격과 상관없이 같습니다(칸 상한에 닿을 때만 조금 다름 — 검토 J02, 검사 `test_growth_interval`). 밭의 성장·상한 배수와 겨울 하한은 6절.
- 사용자 파라미터 **자원량** = `resources.scale`(기본 1). 검사 범위는 0~100 이고, 실험실 패널의 슬라이더는 0~`ui.param.resource_scale_max`(3)까지(그 위는 고급 설정·명령줄 `--set`). **0 이면 먹이가 생기지 않음 → 멸종**(검사 12절).
- 감지용 **누적 합 표(summed-area table)** 는 식물 갱신 때 함께 다시 만들어(식물 + 바닥 먹이) 슬라임의 영역 감지를 O(1)로 합니다. 갱신 사이에는 그대로입니다.

### 1.4 바닥에 놓인 먹이
- 운반하던 먹이를 내려놓으면 칸에 `dropped[c]` 로 쌓입니다. 타이머는 칸마다 하나라서, **마지막으로 내려놓은 틱부터 꼭 `dropped.spoil_ticks`(기본 90)틱 뒤** 그 칸의 더미 전체가 한꺼번에 썩어 사라집니다(더 내려놓으면 더미 전체가 다시 셈 — 검토 I30·J12, 검사 `test_spoil_lifetime`).
- 썩을 때 그 칸이 풀밭이면 확률 `dropped.sprout_chance` 로 **싹이 틈**: 먹이 + `dropped.sprout_food × 자원량`, 비옥도 + `dropped.sprout_fertility`(최대 1 — 그 칸의 본래 비옥도가 오름). 저장고 근처의 싹이 농사 발견의 재료입니다(6절).
- 저장고에 넣은 먹이는 썩지 않습니다. 저장고를 지을 때 그 칸의 바닥 더미를 저장분으로 옮기고(용량을 넘는 몫만 바닥에 남아 썩음), 그 칸에서 죽은 개체의 운반분도 저장분으로 들어갑니다(6절 — 저장고 칸에서는 입력·먹기가 저장분만 보므로 더미가 숨지 않게, 검토 I27).

## 2. 슬라임

### 2.1 상태
살아 있는 개체(필드별 배열 `s_*`, 배열 순서 = id 오름차순)와, 태어난 모든 개체의 계통 기록(`lin_*`, 첨자 = id)이 있습니다.

| 필드 | 뜻 |
|---|---|
| id | 태어난 순서대로 0 부터(정렬·결정성 기준) |
| x, y, head | 칸 좌표, 방향(0 북·1 동·2 남·3 서) |
| energy | 0 ~ 최대 에너지(= `body.energy_per_size` × 크기) |
| age, max_age | 나이(틱), 이 개체의 수명(`life.max_age` ± 흔들림, 2.3) |
| last_repro, last_action | 마지막으로 번식한 틱, 마지막으로 고른 행동(0~7) |
| carry | 운반 중인 먹이(채집 발견 뒤) |
| gen | 세대(초기 개체 0) |
| mem | 기억 뉴런 값(`brain.memory_units` 개, 기본 0개) |
| genome | 신경망 가중치 + 특성 유전자(4절) |
| 계통 기록 | 부모 a·b(초기 개체는 둘 다 −1, 혼자 분열한 자식은 b 만 −1 — 2.4), 세대, 태어난 틱, 죽은 틱, 죽은 이유, 자식 수, 특성 유전자(8.4 `lineage.csv`) |

크기·감지 반경·최대 에너지는 유전체에서 계산하고 저장하지 않습니다. 한 칸에 여러 마리가 있어도 됩니다(충돌 해결 규칙이 필요 없어 결정성이 단순해짐). 화면에서는 칸 안에서 둘레로 비켜 그립니다.

### 2.2 특성 유전자(신경망 외)
| 유전자 | 범위(기본) | 효과 |
|---|---|---|
| size | `traits.size_min`~`size_max`(0.6~1.6), 처음 1.0 | 최대 에너지 ×size, 기본 대사·이동 비용 ×size, 한입·운반 상한 ×size |
| sense | `traits.sense_min`~`sense_max`(1~6), 처음 3 | 유전자는 실수. **감지 반경 = 유전자를 반올림한 칸 수**(floor(유전자 + 0.5), 하한 0.5 이상이라 늘 1칸 이상). 대사 + `metab.sense_cost × 반경` |
| hue | 0~1 | 색. 효과 없음(중립 표지 → 계통이 화면에서 색으로 보임), 느리게 변이(0~1 로 돌아감) |

### 2.3 에너지
- **매 틱 소비** = `metab.base × size + metab.sense_cost × 감지 반경` (+ 앞으로 한 칸을 실제로 옮기면 `metab.move × size`). 쉬기를 고른 틱은 그 합 × `metab.rest_factor`(0.5). **쉬기는 소비만 줄이고 운반분을 먹지 않습니다**(초안 6절의 "운반 중 쉬기·먹기 시 운반분" 가운데 쉬기는 구현하지 않음 — 검토 I61. 운반분은 먹기만 씀).
- **먹기**: 배가 차는 만큼만(최대 (최대 에너지 − 에너지) ÷ 효율), 한 번에 최대 `eat.bite × size`. 저장고 칸이면 저장분, 아니면 식물 → 바닥 먹이 순서로, 그래도 모자라면 운반분에서. 먹은 양 × `eat.efficiency` 가 에너지.
- **죽음**: 행동·대사 뒤 에너지 ≤ 0 → 굶주림, 아니면 나이 ≥ 수명 → 노화. 수명 = `life.max_age`(200) + 태어날 때 고른 정수 [−`life.max_age_jitter`, +jitter](30)(흔들림 < 최대 나이 — 검사). 죽은 개체의 운반분은 그 칸에 남습니다(저장고 칸이면 용량까지 저장분, 나머지는 바닥 먹이).
- **에너지 장부**: 처음 에너지 + 먹은 에너지 − 소비 − 번식 손실(효율 손실 + 자식 상한을 넘은 몫) − 죽은 개체가 남긴 에너지 = 지금 에너지 합. 매 틱 맞는지 검사합니다(`test_energy_ledger` — 발견 전, 운반분·저장분을 먹는 경로, 밭 단계까지. 없는 데서 에너지가 생기지 않음).

### 2.4 번식(규칙 기반, D8)
- 조건(이번 틱에 죽지 않는 개체): 나이 ≥ `repro.maturity`(30), 에너지 ≥ `repro.min_energy_frac` × 최대(0.35), 마지막 번식 뒤 `repro.cooldown`(10)틱 지남, **이번 틱에 아직 짝짓지 않음**(쿨다운 0 이어도 한 틱에 한 번 — 검토 I24).
- 상대: 반경 `repro.mate_radius`(기본 2칸, 정사각형) 안에서 같은 조건을 갖춘 개체 가운데 id 가 가장 작은 개체(결정적). 개체를 id 오름차순으로 처리합니다.
- 자식: 두 부모가 각자 `repro.cost_frac × 지금 에너지`(0.3)를 내놓고, 그 합 × `repro.transfer_efficiency`(0.8)가 자식 에너지 — **자식의 최대 에너지까지**(넘는 몫은 사라지고 장부의 번식 손실로, 검토 I28). 자식은 부모 a 칸에 무작위 방향으로, 세대 = max(부모 세대) + 1. 출생은 모아 두었다가 번식 단계 끝에 배열 뒤에 붙입니다.
- 세계 개체 수 상한 `population.cap`(기본 250): 살아 있는 개체 + 이번 틱 출생이 상한에 이르면 그 틱의 번식을 멈춤(폭주 방지·성능 보호).
- 선택 사항 `repro.asexual_when_alone`(기본 끔): 켜면 짝이 없을 때 **보통 번식 조건만 맞으면** 혼자 분열합니다(에너지가 가득할 필요 없음 — 초안의 "에너지가 가득하면" 은 구현과 달랐음, 검토 I61). 자기 유전체끼리 교차(= 그대로) 뒤 돌연변이, 비용은 자기 몫만. 계통 기록에는 부모 a = 그 개체, **부모 b = −1** 이라 초기 개체는 부모 a 로 가립니다(8.4).

## 3. 감지와 행동

### 3.1 입력(12개 + 기억, 모두 대략 −1 ~ 1)
감지 반경 r = 감지 유전자를 반올림한 칸 수(밤이면 × `sense.night_factor`, 최소 1).

| # | 입력 | 계산 |
|---|---|---|
| 0 | 편향 | 1 |
| 1 | 에너지 | energy / 최대 |
| 2 | 발밑 먹이 | (식물 + 바닥 먹이) / `plants.max_food`. 저장고 칸이면 저장분 / `store.capacity` |
| 3 | 앞쪽 먹이 | 앞쪽 반 영역(앞 r칸 × 폭 2r+1) 식물 + 바닥 먹이 합 / (칸 수 × max_food) (누적 합 표) |
| 4 | 왼쪽 먹이 | 왼쪽 반 영역(옆 r칸 × 2r+1, 모서리는 앞쪽과 겹침) |
| 5 | 오른쪽 먹이 | 오른쪽 반 영역 |
| 6 | 붐빔 | 반경 `sense.crowd_radius`(기본 2, 정사각형) 안 **다른** 개체 수 / `sense.crowd_norm` |
| 7 | 빛 | light(0~1) |
| 8 | 운반량 | carry / (`carry.max` × size) (채집 전에는 늘 0) |
| 9 | 저장고 방향 | 가장 가까운 저장고까지 걷는 거리장(BFS)에서 앞·왼·오른 칸의 거리를 지금 칸과 견줌: 앞 칸이 가까워지고 왼·오른보다 멀지 않으면 0(정면), 아니면 왼쪽 칸이 가까워지고 오른쪽보다 멀지 않으면 −1, 아니면 오른쪽이 가까워지면 +1, 셋 다 가까워지지 않으면(뒤로 돌아야 함) +1. 저장고 칸 위·저장고 없음·닿을 수 없음은 0 |
| 10 | 저장고 가까움 | 1 / (1 + 거리) (없거나 닿을 수 없으면 0) |
| 11 | 계절 온기 | 지금 계절 성장 배수 / 가장 큰 배수(계절 없으면 1) |
| 12~ | 기억 | `brain.memory_units` 개: 직전 판단의 기억 출력을 softsign 한 값(4.1) |

### 3.2 출력(8개)과 행동 고르기
출력 0 앞으로, 1 왼쪽 돌기, 2 오른쪽 돌기, 3 먹기, 4 쉬기, 5 줍기(채집), 6 내려놓기, 7 심기(`SimBrain.ACTION_NAMES` — 화면 이름도 같음). **1·2 는 제자리에서 방향만 90° 바꿉니다** — 칸을 옮기는 것은 0 앞으로뿐입니다(초안 이름 "왼쪽으로"·"오른쪽으로" 는 화면에서 이동처럼 읽혀 "돌기"로 — 검토 I47).

| 행동 | 효과 |
|---|---|
| 앞으로 | 앞 칸이 지도 안이고 지날 수 있으면 옮김(+ 이동 비용). 밭에 들어가면 그 밭의 버려짐 시계를 다시 셈 |
| 왼쪽·오른쪽 돌기 | 방향만 바꿈(이동 비용 없음) |
| 먹기 | 2.3 |
| 쉬기 | 그 틱 소비 × `metab.rest_factor`(운반분은 먹지 않음) |
| 줍기 | 채집 발견 뒤: 발밑 바닥 먹이 → 식물 순서로 한 번에 최대 한입(`eat.bite × size`), 운반 상한 `carry.max × size` 까지. 발견 전: 효과 없음 — 에너지 ≥ `discovery.forage_min_energy_frac` × 최대이고 발밑에 먹이(식물 + 바닥)가 있으면 "배부른 줍기 시도"로 셈(채집 발견의 재료) |
| 내려놓기 | 운반분 전부를 발밑에: 저장고 칸이면 용량까지 저장분(넘는 몫은 계속 듦), 아니면 바닥 먹이 + 저장 발견의 재료(6절). 운반분이 없으면 효과 없음 |
| 심기 | 농사 발견 뒤, 운반분 ≥ `farm.seed_cost` 이고 앞 칸이 풀밭(저장고 아님, 저장고까지 걷는 거리 ≤ `farm.radius`)이면 그 칸을 밭으로(운반분 − seed_cost). 그 밖에는 효과 없음 |

- **확률적 정책(기본 `brain.policy = "sample"`)**: 출력 o 마다 z = softsign(o), 가중치 (1 + z)^k (k = `brain.sharpness`, 기본 4, 거듭 곱셈만 씀)에 비례하는 확률로 행동을 뽑습니다(생명 난수 흐름). 가중치가 크게 진화하면 거의 결정적이 됩니다. `"argmax"` 로 바꾸면 가장 큰 출력(같으면 번호가 작은 쪽). (초안은 argmax 였으나 무작위 두뇌가 거의 한 행동만 반복해 첫 세대가 멸종 → 17절)
- 여덟 행동은 언제나 고를 수 있습니다. 아직 열리지 않은 행동은 고르기만 하고 효과가 없습니다. 발견의 재료로 세는 것은 채집 전 "배부른 줍기 시도" 하나이고, 저장·농사의 재료는 실제로 내려놓은 양·저장고 근처 싹입니다(6절). 고른 행동은 `last_action` 에 남아 정보 창이 "고른 행동 줍기 (시도 · 발견 전)" 처럼 흐리게 보이고, 지도에서도 그런 시도는 끄덕이지 않고 숨쉬기만 합니다(검토 I86).
- 판단 간격 `brain.think_every`(기본 1틱): (틱 + id)가 그 배수일 때 판단하고, 그 사이에는 직전 행동을 반복합니다. (2 로 시험했더니 먹기·돌기 반복 낭비로 첫 세대가 멸종해 1 로 둠 → 17절)

## 4. 두뇌(D1 — 확정: A)

### 4.1 고정 구조 앞먹임 신경망
```
입력 12 + 기억 m ──(가중치)──▶ 은닉 8 (softsign: x / (1 + |x|)) ──(가중치)──▶ 출력 8 + 기억 m (선형)
  행동 = 출력 0~7 에서 sample 정책(기본, 3.2) 또는 argmax
  기억 출력 m 개 → softsign → 다음 판단의 입력 12~(12+m−1)
```
- 가중치 12×8 + 8×8 = 160개 + 특성 유전자 3개 = **유전체 163개 실수**(기억 2 면 14×8 + 10×8 + 3 = 195). 편향은 늘 1 인 입력 0 이 맡습니다. 배치(`SimBrain.layout`): [은닉 j 마다 입력 n_in 개] [출력 q 마다 은닉 수(`brain.hidden`, 기본 8)만큼] [size, sense, hue].
- **softsign** 은 사칙연산만 쓰므로 Windows·Linux·macOS 에서 비트 단위로 같은 결과를 기대합니다(tanh·exp 는 C 라이브러리마다 마지막 비트가 다를 수 있음).
- 가중치는 **float32 로 저장**(PackedFloat32Array), 계산은 float64. 태어날 때 float32 로 반올림해 두므로 저장·복원이 비트 단위로 정확합니다.
- **교차:** 뉴런 단위 — 은닉 뉴런 j 의 들어오는 가중치(n_in 개)와 나가는 가중치(출력 수만큼, 기억 출력 포함)를 한 덩어리로 보고, 덩어리마다 부모 a·b 중 하나를 고름(무작위 0.5). 특성 유전자는 각각 고름. 같은 역할 뉴런이 함께 움직여 "평균하면 망가지는" 문제를 줄입니다.
- **돌연변이:** 가중치마다 확률 `mutation.rate`(사용자 파라미터, 기본 0.05)로 + N(0, `mutation.sigma`)(기본 0.3), ±`brain.weight_clamp`(기본 4)로 자름. 특성 셋도 각각 같은 확률로 N(0, sigma × `traits.mutation_scale_*`) — 크기·감지는 범위로 자르고 색은 0~1 로 돌림. N(0,1)은 균등 난수 4개 합(어윈-홀, 평균·분산을 맞춤) — log·cos 를 쓰지 않기 위해.
- 초기 개체: 가중치 균등 [−`brain.init_range`, +], 특성 = `traits.*_init`, 색 균등. 처음 세대가 살아남도록 시작 먹이를 넉넉히(`plants.initial_fill`) 채웁니다.

## 5. 상속과 진화 요약
- 유전체 = 가중치 + size·sense·hue. 교차(4.1) → 돌연변이 → float32 반올림 → 범위 자르기.
- 평생 학습은 없습니다(D3). 개체가 겪은 것은 유전되지 않고, 세계의 **발견**만 누적됩니다.
- 계통 기록: 태어난 모든 개체의 (id, 부모, 세대, 태어난 틱, 죽은 틱, 죽은 이유, 자식 수, 특성 유전자)를 남깁니다. 화면의 가계도와 `lineage.csv` 의 원천(8.4).

## 6. 발견과 건물(규칙 기반 문명 층)

발견은 **세계 전체**가 공유하고(D5), 순서는 채집 → 저장 → 농사로 고정입니다(앞 단계가 열려야 다음 재료를 셈).

| 단계 | 재료(셈 조건) | 임계(config) | 열리는 것 |
|---|---|---|---|
| 1 채집 | "배부른 줍기 시도": 채집 발견 전, 에너지 ≥ `discovery.forage_min_energy_frac`(0.8) × 최대인 개체가 먹이(식물 + 바닥)가 있는 칸에서 줍기(5)를 고른 횟수, 누적(발견 뒤에는 세지 않음) | `discovery.forage_threshold`(기본 300) | 줍기·내려놓기(3.2). 운반분은 먹기에서 칸 먹이가 모자랄 때 씀(쉬기는 운반분을 먹지 않음 — 2.3). 죽으면 운반분이 그 칸에 남음 |
| 2 저장 | "모아 놓기": 채집 발견 뒤 내려놓기(6)로 **저장고가 아닌 칸에** 내려놓은 먹이 양을 `discovery.region_size`(8)칸 정사각형 구역마다 누적 | `discovery.store_threshold`(기본 60) — 어느 구역이든 | 그 구역에서 가장 많이 놓인 칸(같으면 번호 작은 칸, 저장고 칸·지날 수 없는 칸 빼고)에 **저장고**. 첫 저장고가 저장 발견입니다. 그 칸의 바닥 먹이 더미는 저장분으로(용량까지 — 검토 I27). 그 칸이 밭이면 짓지 않음(검토 J13). 짓든 못 짓든 그 구역 셈은 0 으로 |
| 3 농사 | "저장고 근처 싹": 저장고까지 걷는 거리 ≤ `discovery.farm_radius`(6)인 풀밭에서 썩은 먹이가 싹튼 횟수, 누적(저장고가 있으면 늘 셈 — 농사 발견 뒤에도) | `discovery.farm_threshold`(기본 15) — 저장 단계에서 | 심기(3.2): 운반 먹이 `farm.seed_cost`(1)를 써서 앞 칸(풀밭, 저장고까지 거리 ≤ `farm.radius`(5))을 **밭**으로. 밭은 비옥도 1, 성장 × `farm.growth_mult`(2.5), 상한 × `farm.max_mult`(1.5), 계절 배수 = max(계절 배수, `farm.winter_floor`(0.4)) — 겨울에도 조금 자람 |

**건물 2종**
| 건물 | 크기 | 생기는 방법 | 규칙 |
|---|---|---|---|
| 저장고 | 1칸(통과 가능) | 저장 발견 때 1개. 그 뒤 어느 구역이든 다시 임계를 넘으면 그 구역의 가장 많이 놓인 칸에 — 기존 저장고와 맨해튼 거리 `store.min_spacing`(12) 이상이고 모두 `store.max_count`(4 — 첫 저장고 포함이라 1 이상, 검토 I25) 안일 때만 | 용량 `store.capacity`(200). 저장분은 썩지 않음. 저장고 칸에서 먹으면 저장분을, 내려놓으면 용량까지 저장. 지을 때마다 거리장(BFS)을 다시 계산해 입력 9·10 갱신 |
| 밭 | 1칸 | 심기 행동 | 개체가 걸어 들어온(또는 심은) 마지막 틱에서 `farm.abandon_ticks`(300)틱이 넘도록 아무도 들어오지 않으면 풀밭으로(본래 비옥도). **매 틱** 판정 — 밭 성장 속도·식물 갱신 간격과 상관없음(검토 J03). 버려진 마을이 보이게 |

- 발견 순간은 연대기에 "채집 발견 — 배부른 줍기 시도 300회 (평균 37.2세대)" 처럼(저장은 "구역에 모아 놓은 먹이 60", 농사는 "저장고 근처 싹 15번") 기록하고 화면에 알림·합성 종소리. 저장고마다 "저장고 N호 — (x, y)", 첫 밭은 세계에서 **한 번만** "첫 밭 — #id, (x, y) 에 심음"(밭을 모두 잃고 다시 심어도 다시 나오지 않음 — 검토 I26), 버려진 밭은 틱마다 "버려진 밭 N곳이 풀밭으로 돌아감" 한 줄. 사건 종류는 8.4·19절.
- 발견 후 압력: 채집·저장이 열리면 겨울을 버티는 계통이 유리해져 행동이 진화로 강화되는지가 관찰 대상입니다. 이것이 연구 질문이며, 결과가 어떻게 나오든 그대로 보고합니다.
- 임계가 너무 낮으면 "우연한 행동만으로" 문명이 열립니다. 기본값은 첫 측정 뒤 조정했고(17절), 연구용 `fast_civ` 를 고른 근거는 [`TUNING-fast_civ.md`](TUNING-fast_civ.md) 입니다.
- **검토 고침의 규칙 고침(21절) 뒤 발견이 꽤 빨라졌습니다.** 임계는 다시 맞추지 않았습니다. 기본값 씨앗 1~12 의 농사 도달은 7/12 → 9/12(중앙값 38.0 → 26.9세대), 기본·씨앗 1 의 1,000세대 실행에서 농사는 140.7 → 56.6세대(9,440 → 3,779틱) — **기본값으로도 씨앗 1 이 100세대 안에 농사**에 닿습니다. `fast_civ` 는 농사 중앙값 15.9 → 14.3세대(12/12 그대로)로, 목표(저장 15~35·농사 30~70세대)를 고침 전에도 못 맞췄고 지금은 더 이릅니다(TUNING "목표와 다른 점"). 씨앗 1·7 은 농사를 연 뒤 멸종합니다.

## 7. 결정성(D10)

- **같은 씨앗 + 같은 파라미터 + 같은 실행 파일 = 같은 역사.** 비트 단위로 같아야 하며 매 실행 끝에 **역사 해시**를 냅니다.
- 난수: `SimRng` 가 Godot `RandomNumberGenerator`(PCG32)의 정수 출력 `randi` 만 쓰고, 실수([0, 1) = randi ÷ 2^32)·정규 근사는 사칙연산·sqrt 로 직접 만듭니다(`randf`·`randfn` 은 쓰지 않음). `RandomNumberGenerator` 는 `sim_rng.gd` 밖에서 만들 수 없습니다(검사). 흐름 둘: `rng_world`(씨앗 그대로 — 싹 확률), `rng_life`(씨앗에 상수를 섞음 — 초기 개체 자리·방향·나이·유전체, 수명 흔들림, 행동 뽑기, 교차·돌연변이, 자식 방향). 지형은 난수 흐름이 아니라 씨앗의 해시(1.2). 두 흐름의 상태는 스냅숏에 글자로.
- 처리 순서: 모든 반복은 id 오름차순 또는 칸 번호 오름차순. Dictionary 순회 결과에 의존하지 않음. 출생은 번식 단계 끝에 일괄 추가, 사망은 사망 정리 단계에서 일괄 제거(순서 보존 압축).
- 수학: 시뮬레이션 코드(`scripts/sim`)는 허용 목록의 함수·메서드만 씀 — 7.1.
- 역사 해시: 세계를 만든 끝과 진행한 뒤 틱이 `hash.every`(기본 100)의 배수일 때마다, "앞 해시 | 틱 | 개체 수 | id 합 | 위치·방향 합 | 문명 단계 | 에너지 합 · 유전자 합 · 식물 먹이 합 · 저장 내려놓기 누적(각각 float64 비트 16진)" 을 SHA-256 으로 이어 붙입니다(64자 — `summary.json` 에 전체, RESULT 줄에는 앞 12자). 검사점 사이 틱의 차이는 담지 않으므로 "두 세계가 지금 같은 상태인가"는 스냅숏 글 전체(`SimSnapshot.to_text`)로 견줍니다(검사들이 그렇게 함 — 검토 I89).
- **플랫폼 간:** CI 는 Linux 에서 검사합니다. Windows·macOS 에서 같은 해시가 나오는지는 설계상 기대하지만 **미검증**입니다(TEST-REPORT). 확인하는 법: Windows 콘솔 판 Godot 로 같은 실행기 명령(11절, 명령은 [`ANALYSIS.md`](ANALYSIS.md) "Windows")을 돌려 RESULT 줄의 `hash=` 를 Linux 와 견줌. 웹(wasm)은 같은 해시를 확인했습니다(20절 — 자동 검사는 아님).

### 7.1 매직 넘버·허용 함수 검사(`test_static_rules`)
- `scripts/sim/*.gd`(설정 로더 `sim_config.gd` 는 범위 상·하한이 있어 매직 넘버만 뺌)에서 주석·문자열을 뺀 코드의 수 글자는 `0, 1, 2, 0.0, 1.0, 0.5` 만 씁니다(음수 −1 은 1 로 셈, `const` 줄은 이름 붙은 상수라 뺌). `1_000`·`.25`·`0b1`·`1e6`·`2.0` 처럼 다른 꼴로 적은 수도 모두 매직 넘버입니다. 모든 시뮬레이션 수치는 `config/sim-defaults.json` 에서 읽습니다(밤 문턱도 `time.night_light_threshold` — 검토 I77).
- 함수 호출은 금지 목록이 아니라 **허용 목록**입니다(`ALLOWED_GLOBAL_CALLS`·`ALLOWED_METHODS` — 사칙연산·sqrt·비교·정수 연산·배열·글자·파일 다루기뿐, 시뮬레이션 파일에 정의한 함수는 저절로 허용). `**` 와 `sim_rng.gd` 밖의 `RandomNumberGenerator` 도 거부합니다. 검사기가 위반 꼴을 실제로 잡는지도 함께 봅니다(검토 I36 — 예전 금지 목록은 asin·ease·전역 randf 를 놓쳤음).

## 8. 데이터 구조와 형식(D2 — 확정: A)

### 8.1 시뮬레이션 내부(구조 배열, SoA)
슬라임은 객체가 아니라 필드별 Packed 배열입니다(`s_id`, `s_x`, `s_y`, `s_head`, `s_age` … 는 `PackedInt32Array`, `s_energy`·`s_carry`·`s_mem` 은 `PackedFloat64Array`, 유전체 `s_genome` 은 `PackedFloat32Array` 하나에 개체 × 유전자 수). 계통은 id 를 첨자로 하는 `lin_*` 배열, 지도는 칸 번호를 첨자로 하는 배열입니다. GDScript 에서 객체보다 빠르고, 나중에 C#/GDExtension 으로 옮길 때 그대로 배열 경계가 됩니다(이름 목록은 8.3 표).

### 8.2 설정

- 실험 = 기본값 + 예설정 + 사용자 덮어쓰기(파라미터 패널·명령줄 `--set=절.키=값`). 덮어쓰기는 **잎 키**만(절에 사전을 넣으면 거부 — 검토 I02). 결과 폴더·스냅숏에 **실제로 쓴 전체 설정**을 함께 저장합니다.
- **설정 검사(D11, 사용자 결정 2026-10-10: 이름표에 적힌 범위를 모두 실제 검사로)** — `SimConfig.validate`:
  - 구조: 빠진 키·모르는 키·값 종류(수·참거짓·글자·배열)·배열 길이가 기본값과 같음(`_` 로 시작하는 설명 키는 뺌).
  - 범위: 수 키는 `SimConfig.RULES` 의 [하한, 상한] — 나눗수로 쓰이는 키는 "0 초과"(0 이면 0 으로 나눔·NaN 두뇌 — 검토 I01), 지형 격자 간격 1 이상, 감지 유전자 0.5 이상(반올림해 1칸 이상). 배열 원소는 `ARRAY_RULES`, 글자는 `CHOICES`(`"sample"`/`"argmax"`).

### 8.3 스냅숏(저장·복원) — 형식 1
`SimSnapshot.to_dict` 가 만드는 JSON 사전 하나입니다(키는 이름순으로 씀). 엔진과 무관하게 파이썬·C# 에서 읽을 수 있게 형식을 여기에 고정합니다(`sim_snapshot.gd` 의 키 상수 `MAP_B64`·`CIV_*`·`SLIMES_B64`·`LINEAGE_B64`·`STATS_*` 와 같음).

**값 꼴:**
- **배열** = 원소를 리틀엔디언 바이트로 이어 붙인 base64 글자(빈 배열은 `""`). 원소 형식: `i32` 부호 있는 32비트 정수, `f64` 64비트 실수, `f32` 32비트 실수, `u8` 부호 없는 8비트.
- **단일 실수**(장부 등) = float64 리틀엔디언 8바이트의 16진 글자 16자(`SimSnapshot.f64_hex`).
- **64비트 정수**(씨앗·난수 상태) = 10진 글자. 그 밖의 정수 = JSON 수.
- 실수를 JSON 수로 두지 않는 까닭: Godot 4.4.1 의 `JSON.stringify(…, full_precision = true)` 가 0.1+0.2 를 `0.3` 으로, 1e-300 을 `0` 으로 써서 비트 왕복이 안 되는 것을 구현 중 확인했습니다. 설정만은 사람이 읽도록 JSON 수로 두고 8.2 의 JSON 왕복 검사로 지킵니다.
- 길이 기호: **C** = 칸 수(너비 × 높이), **n** = 살아 있는 개체 수(`slimes.count`), **L** = 태어난 모든 개체 수(`lineage.count`, id = 0 … L−1), **S** = 저장고 수, **m** = `brain.memory_units`, **G** = 유전자 수(163, 기억 2 면 195 — 4.1).

- **읽을 때 검사**(`SimSnapshot.validate`·`validate_world`): format·version 1, 모든 절·키와 값 꼴(base64 글자, 정수, 16진 16자이고 유한한 수), 설정(8.2 검사 — 나중에 더한 설정 키 `SimSnapshot.CONFIG_KEYS_ADDED`, 지금 `time.night_light_threshold` 가 없는 옛 파일은 그 키를 기본값으로 채움), 배열 길이, 칸 번호·위치·방향·행동·부모 id·사망 원인의 범위, **유전체 길이 = 설정에서 계산한 길이**, 유한한 실수. 칸 번호는 검사가 끝난 뒤에야 첨자로 씁니다(구조가 틀린 파일도 스크립트 오류 없이 오류 문장 — 검토 I04, 검사 `test_snapshot_corrupt`).

### 8.4 실험 결과 폴더(헤드리스·화면 공통) — 결과 파일의 정본
| 파일 | 내용 |
|---|---|
| `summary.json` | 씨앗, 실제 설정, 끝난 이유, 틱, 발견 틱, 역사 해시, 실행 시간 등(아래 표) |
| `timeseries.csv` | 처음(틱 0 또는 이어 돌린 스냅숏 틱) 한 줄, `record.every`(기본 20)틱의 배수마다 한 줄, 끝난 틱이 배수가 아니면 끝 줄(멸종이면 멸종한 틱) |
| `chronicle.csv` | 연대기(발견·저장고·첫 밭·밭 잃음·세대 이정표·멸종) |
| `lineage.csv` | 태어난 모든 개체 한 줄씩(`--no-lineage` 로 끔) |
| `final.snapshot.json` | 마지막 상태(8.3) — 이어서 돌리거나 화면에서 열기 |
| `snapshot-<틱>.json` | 실행기 `--snapshot-every` 의 중간 스냅숏 |

**꼴:** CSV 는 **BOM 붙은 UTF-8**(EF BB BF — 사용자 결정 2026-10-10: 한국어 Windows 엑셀이 두 번 클릭으로 열어도 연대기·단계 이름이 깨지지 않게. pandas·LibreOffice·파이썬 `csv`(`encoding="utf-8-sig"`)는 그대로 읽고, R 은 `read.csv(파일, fileEncoding = "UTF-8-BOM")`), 쉼표, 줄 끝 `\n`, 영문 snake_case 열 이름, 소수점 `.`, 실수는 소수 최대 6자리, 쉼표·따옴표·줄바꿈이 든 글은 큰따옴표로 감쌈. JSON(`summary.json`·스냅숏)에는 BOM 이 없습니다. 화면의 글자는 한국어. 실험실 "CSV 내보내기"와 헤드리스 실행기는 같은 기록기(`SimRecorder`)를 써서, 같은 씨앗·설정·틱이면 CSV·스냅숏이 바이트까지 같습니다(검사). `analyze.py` 가 쓰는 CSV(`summary.csv`·`cells.csv`·`runs.csv`)도 BOM 붙은 UTF-8 입니다([`ANALYSIS.md`](ANALYSIS.md)).

**쓰는 순서:** (중간 스냅숏) → `final.snapshot.json` → `timeseries.csv`·`chronicle.csv`·`lineage.csv` → `summary.json`(임시 이름으로 쓴 뒤 바꾸기, **마지막**). CSV 를 하나라도 못 쓰면 `summary.json` 은 쓰지 않으므로 **`summary.json` 이 있으면 다 쓴 결과**입니다. `summary.json` 의 `write_failed` = 그보다 먼저 쓰지 못한 파일(중간·최종 스냅숏). 쓴 길이를 다시 읽어 확인하므로 디스크가 차서 잘린 파일도 실패로 셉니다.

**틱 기준(검토 J26).** 세계의 `tick` 은 진행한 틱 수이고, 틱 t 를 진행하는 동안(9절의 ①~⑦) 생긴 일은 **진행 중인 틱 번호 t** 로, 진행을 마친 뒤의 상태는 **틱 t+1** 로 적습니다.

| 진행 중인 틱 번호로 적는 것 | 진행한 뒤 틱으로 적는 것 |
|---|---|
| `lineage.csv` 의 `birth_tick`·`death_tick`, `summary.json` 의 `discovery_ticks`, 연대기 `discovery`·`store_built`·`first_farm`·`farm_lost`, 실험실 알림 "틱 N" | `timeseries.csv` 의 `tick`, `summary.json` 의 `tick`·`extinct_tick`, 연대기 `milestone`·`extinction` |

그래서:
- 개체는 `birth_tick` < t ≤ `death_tick` 인 줄 t 에 있습니다(초기 개체만 `birth_tick` 0 이고 틱 0 줄부터 있음: 0 ≤ t ≤ `death_tick`. `death_tick` −1 = 끝까지 살아 있음). 흔한 읽기(birth ≤ t < death)는 한 줄씩 어긋납니다.
- 줄 t 의 `births`·`deaths` = 태어난(죽은) 틱 번호가 [앞 줄 틱, t) 인 개체 수.
- `extinct_tick` = 마지막 `death_tick` + 1(그 줄의 `population` 0). 처음부터 개체가 없는 세계는 0.
- 틱 T 의 발견·저장고·첫 밭·밭 잃음은 줄 tick ≥ T+1 부터 `civ_stage`·`storehouses`·`farms` 에 보입니다(T 가 기록 줄의 틱과 같으면 그 줄에는 아직 없고 다음 줄부터).
- 연대기 `mean_gen` 의 기준: 채집·농사 발견과 `milestone` 은 그 틱을 진행한 뒤 살아 있는 개체(틱 T+1 상태), 저장 발견·`store_built`·`first_farm`·`farm_lost` 는 진행 전 개체(틱 T 상태 — 행동 도중·틱 처음에 일어남), `extinction` 은 마지막 틱에 죽은 개체들의 평균 세대. `analyze.py` 의 발견 세대는 이 값입니다.

**`timeseries.csv`** (열 순서 그대로, "구간" = 앞 줄 뒤 이 줄까지, "누적" = 처음부터, 그 밖은 이 줄 틱의 값)

| 열 | 뜻 |
|---|---|
| `tick` | 진행한 틱 수 |
| `day` | tick ÷ `time.day_ticks`(정수 나눗셈, **0 부터** — 화면의 "날"은 이 값 + 1) |
| `season` | 0 봄·1 여름·2 가을·3 겨울, −1 = 계절 없음(`time.season_days` 0) |
| `light` | 빛 0~1 |
| `population` | 살아 있는 개체 수 |
| `births`, `deaths` | **구간** 출생·사망 수(`sample()` 이 세고 0 으로 되돌림 — 처음부터 돌린 실행이면 열 합 = `summary.json` 의 `total_births`·`total_deaths`) |
| `mean_gen`, `mean_energy`, `mean_size`, `mean_age` | 살아 있는 개체의 평균 세대·에너지·크기·나이 |
| `mean_sense` | 평균 **감지 반경**(유전자를 반올림한 칸 수의 평균 — `lineage.csv` 의 `sense` 유전자 평균과 다름. 예: `fast_civ`·씨앗 2·1,300틱 끝 줄 2.996, 살아 있는 개체의 `sense` 평균 2.983) |
| `food_total`, `dropped_total`, `stored_total`, `carry_total` | 지도 전체 식물 먹이·바닥 먹이·저장분·운반분 합 |

| `storehouses`, `farms` | 저장고·밭 수 |

| `farm_sprouts` | **누적** 저장고 근처 싹 수(농사 발견 뒤에도 계속 셈) |

개체가 0 인 줄(멸종한 틱)의 평균 열은 `0.0` 입니다 — 평균을 그릴 때는 `population > 0` 으로 거르세요(화면 그래프·`analyze.py` 는 거름).

**`chronicle.csv`**: `tick`(위 표의 기준), `mean_gen`(0.01 단위로 반올림한 평균 세대 — 위 기준), `kind`, `actor_id`(−1 = 없음, `first_farm` 은 심은 개체 id), `text`(한국어 문장). `kind` 는 `discovery`(단계는 문장 머리 "채집·저장·농사 발견 — …"), `store_built`, `first_farm`(세계에서 한 번), `farm_lost`, `milestone`(`record.generation_milestone` 세대마다), `extinction`(처음부터 개체가 없으면 틱 0).

**`lineage.csv`**

| 열 | 뜻 |
|---|---|

### 8.5 다른 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. JSON + base64 이진 배열 (택함)** | 메타는 사람이 읽음, 부피 작음(200마리 유전체 원본 약 130KB), 정확한 왕복, 엔진 독립(C#·파이썬에서 8.3 표대로 읽음) | 배열 부분은 눈으로 못 읽음 |
| B. 전부 JSON 숫자 | 완전히 사람이 읽음 | 크기 3~5배, 실수 왕복이 안 됨(8.3) |
| C. Godot `var_to_bytes`/리소스 | 구현 가장 짧음 | Godot 전용·버전 의존, C# 이식·외부 분석에 불리 |

- 화면이 쓰는 질의·상수의 고정 목록은 [`SIM-API.md`](SIM-API.md) 입니다(초안의 `slime_count()`·`slime_pos(i)`·`tile_food(c)`·`buildings()` 같은 이름은 만들지 않았고, 실제는 `population()`·`s_x[i]`/`s_y[i]`·`food[c]`·`store_tiles`/`farms`·`step()`/`step_n(n)`·`drain_events()` 등). 같은 이름·뜻을 갖는 C#/GDExtension 구현으로 바꿔 끼울 수 있게 하는 경계이고, `tools/test_repo_rules.py` 가 화면 코드가 이 목록 밖의 이름을 쓰지 않는지·세계를 바꾸지 않는지 검사합니다.
- **한 틱 순서**(`sim_world.gd` 머리 주석과 같음):
  ① 빛·계절 계산, 버려진 밭 → 풀밭(매 틱)
  ② (`plants.update_every` 마다) 식물 성장·누적 합 표
  ③ 슬라임마다(id 오름차순) 감지 → 판단 → 행동 → 대사·나이 → 죽음 표시. **내려놓기 순간에** 구역 셈 → 저장고 짓기·저장 발견(같은 틱 뒤 차례 개체는 그 저장고를 바로 쓰고 입력 9·10 으로 봄 — 검토 I29, 검사 `test_store_built_in_act`)
  ④ 번식(짝짓기 id 오름차순, 출생은 끝에 붙임)
  ⑤ 사망 정리(계통에 죽은 틱·원인, 운반분 내려놓기)
  ⑥ 바닥 먹이 썩음·싹(저장고 근처 싹 셈)
  ⑦ 채집·농사 발견 판정
  ⑧ 틱 + 1, 빛·계절을 새 틱으로 다시(틱 사이의 `light`·`season` 은 언제나 지금 틱), 최고 인구·멸종·세대 이정표, `hash.every` 의 배수면 역사 해시
  기록 줄은 세계 밖 기록기가 ⑧ 뒤에 `sample()` 로 남깁니다(8.4).

## 10. 화면 구성(실험실)

- **슬라임 모델:** 이전 `demon_geo.gd` 의 `sculpt()`(방향별 반지름 함수로 구 변형)를 가져와 아래가 납작하고 위가 둥근 물방울형, 두 눈은 같은 메시의 정점 색. 표정·뼈대 없음(MultiMesh 이므로). 삼각형 예산 `ui.slime.triangles_max`(기본 400).
- **건물:** 저장고 = `lathe()` 회전체(둥근 움집 + 뚜껑), 밭 = 칸 위 이랑 줄무늬 판. 코드로 생성.
- **클릭:** 화면 광선을 슬라임 몸 삼각형과 교차해 가장 앞 개체(빗나가면 몸 중심 높이 평면에서 반경 안 가장 가까운 개체 — 검토 I53) → 오른쪽 정보 창(상태·특성·**고른 행동**(발견 전 줍기·심기는 "(시도 · 발견 전)" 흐리게)·운반("먹이 0.6" 처럼 단위)·두뇌 가중치 열지도(범례 끝은 `brain.weight_clamp` 를 반올림하지 않은 값)·부모·조부모·자식 목록, 이름 대신 #id 와 색 점). 가계 항목을 누르면 그 개체(살아 있으면 지도에서, 죽었으면 기록)로 이동.
- **파라미터 패널:** 돌연변이율·자원량·초기 개체 수·씨앗(64비트 정수 글 칸 — 소수·식은 줄 아래 오류) + 예설정. 바꾸면 **새 실험**을 눌러야 적용(진행 중 실험의 조건이 섞이지 않게). 고급 설정은 접어 두고 config 키 이름 그대로 표시(한국어 이름·뜻·범위는 말풍선 — `sim-labels.json`), 범위 밖 값은 그 줄 바로 아래 오류(8.2). 단추·고르기 상자는 Tab 으로 닿고 Enter 로 누름(스페이스는 멈춤), Ctrl(맥 Cmd)+N·S·O·E = 새 실험·스냅숏 저장·열기·내보내기.
- **속도:** 1~64배와 빨리 감기. 시뮬레이션은 프레임당 시간 예산(`ui.speed.sim_budget_ms`, 기본 10ms) 안에서만 돌리고, 따라가지 못하면 "목표 64배 / 실제 23배" 로 정직하게 표시합니다(실제 배속은 프레임 사이 벽시계로 잼 — 검토 J04).
- **위쪽 막대:** 틱·날·계절·낮/밤(그 세계의 `time.night_light_threshold`)·평균 세대·개체 수·문명(비교 모드는 A·B 의 개체 수·문명)·속도. 멸종한 세계는 더 진행하지 않고(헤드리스 실행기처럼) 지도 왼쪽 위에 "멸종 · 틱 N" 표지를 남기며, 모든 실험이 멸종이면 속도 자리가 "멸종 · 진행 끝"(검토 I13).
- **그래프 3개:** 직접 그리는 Control(`_draw`). ① 개체 수(+출생·사망) ② 평균 특성(크기·감지·에너지·나이·세대 중 고름 — "감지"는 반올림 반경의 평균) ③ 기술 단계 계단선 + 저장고·밭 수 띠 + 발견 표시. 가로축은 틱/세대 전환. 스냅숏에서 연 실험은 연 틱부터 다시 기록하므로 그래프 머리에 "기록은 틱 N 부터"(검토 J19).
- **연대기:** 줄을 누르면 그래프에 그 시점 표시. 실제 사건 종류는 19절(초안의 멸종 위기·최대 인구·우세 계통 교체는 1단계에서 넣지 않음).
- **CSV 내보내기:** 8.4 와 같은 폴더 구성을 사용자가 고른 폴더(기본 `user://experiments/<시각>-seed<N>/`)에 씀.
- **비교 모드:** 실험 A·B 를 각자 설정으로 만들어 지도 창 둘을 나란히(SubViewport 2개), 틱마다 A 다음 B 로 같은 속도. 한쪽이 멸종하면 그쪽은 멸종 틱에 멈추고 살아남은 쪽만 진행(위쪽 막대 틱 "A/B"). 그래프는 한 축에 A 실선·B 점선으로 겹침. 연대기는 A/B 표시.
- **소리:** 발견 차임·멸종 낮은 음·저장고 "톡" 3종(19절), 실행 중 파형 합성(AudioStreamWAV). 패널에서 끄기. 글꼴은 나눔고딕 보통·굵게(`assets/fonts/NanumGothic-*.ttf`, NHN Corporation, SIL OFL 1.1 — 전문 `assets/fonts/OFL-NanumGothic.txt`)를 프로젝트 기본 글꼴로 쓰고 CREDITS 에 기록(3단계에서 바꿈, 18절).

## 11. 헤드리스 실행기

```
godot --headless --path . --script res://tests/run_experiment.gd -- \
    --seed=42 --generations=1000 --out=results/seed42 \
    [--preset=default] [--set=mutation.rate=0.08 --set=plants.regrow=0.3] \
    [--max-ticks=2000000] [--no-lineage] [--snapshot-every=10000] [--resume=path/to/snapshot.json] [--quiet]
```
- 끝나는 조건(이 순서로 봄): 멸종 → 살아 있는 개체 평균 세대 ≥ `--generations` → 틱 ≥ 상한(`--max-ticks`, 없으면 설정 `run.max_ticks` 2,000,000). 끝난 이유를 `summary.json` 의 `end_reason` 과 마지막 줄에 표시합니다. 위 명령을 실제로 돌린 줄(2026-10-10, 검토 고침 뒤):
  `RESULT: seed=42 generations=1000.0 ticks=113250 pop=250 civ=3(농사) hash=e2c5d2ab8a53 time=756.9s reason=generations`
  (`hash` 는 앞 12자, `time` 은 기계에 따라 다름 — 13절. 쓰기에 실패하면 끝에 ` write_failed=파일(까닭),…` 가 붙음)
- 인자 규칙: `--seed` 는 64비트 정수, `--generations` 는 0 보다 큰 유한한 수, `--max-ticks` 는 1~1,000,000,000(`SimConfig.TICK_MAX`), `--snapshot-every` 는 0(끔)~1,000,000,000 의 정수 — `1e5`·`10k` 처럼 글자가 섞이면 앞 숫자만 쓰지 않고 인자 오류. 상대 경로는 프로젝트 폴더(`--path`) 기준. 진행 표시는 10초마다 한 줄(틱/초 포함, `--quiet` 면 없음).
- **종료 코드**: **0** 정상 · **2** 인자·설정·결과 폴더 오류(모르는 인자, 8.2 설정 검사, 이어 돌릴 스냅숏을 읽지 못함, `--resume` 과 함께 준 `--seed`·`--preset`·`--set`, 실행기가 모르는 파일이 있는 `--out`) · **3** 파일 쓰기 실패(중간·최종 스냅숏, CSV, `summary.json` — 실패마다 오류 줄, 결과 폴더를 열거나 앞 결과를 지울 수 없을 때도) · **1** 은 실행기가 내지 않습니다(Godot 이 스크립트를 읽지 못하면 엔진이 1 로 끝냄). CI 와 `analyze.py` 는 종료 코드와 줄 끝까지 맞춘 `reason=generations$` 로 판정합니다. (검사 실행기 `run_tests.gd`·`run_view_tests.gd` 는 다른 약속: 모두 통과 0, 실패나 `--only` 의 모르는 이름 1 — 12절.)
- **`--resume`**: 설정·씨앗은 스냅숏의 것을 씁니다(`--seed`·`--preset`·`--set` 을 함께 주면 무시하지 않고 2). 이어 돌린 것과 끊김 없이 돌린 것은 **같은 역사 해시**입니다 — 검사 `tools/test_runner_cli.py` `TestResume`(실행기를 명령줄 그대로 불러 `--snapshot-every` 의 중간 스냅숏에서 이어 돌림, 검토 I63). 이어 돌린 `summary.json` 은 `preset ""`·`overrides {}`·`resumed_from`(실제로 읽은 파일)·`resume_status`(`loaded`, 본 파일이 깨져 `.bak` 에서 읽었으면 `backup` + 경고 줄). 이어 돌리자마자 끝나도 시계열은 그 틱 한 줄. 이어 돌릴 스냅숏이 `--out` 폴더 바로 안이면 2.
- **결과 폴더(`--out`)**: 없거나 비었으면 그대로 쓰고, 실행기가 쓰는 파일만 있으면 모두 지우고 새로 쓰며(앞 실행의 `lineage.csv`·`snapshot-N.json`·`.bak` 이 섞이지 않게), 그 밖의 파일·하위 폴더가 하나라도 있으면 아무것도 지우지 않고 2. 설정 오류는 폴더를 보기 전에 거르므로 앞 결과가 남습니다. 자세한 규칙과 Windows 콘솔 판(`Godot_v4.4.1-stable_win64_console.exe`)은 [`ANALYSIS.md`](ANALYSIS.md) "헤드리스 실행기를 직접 쓸 때"·"Windows".

## 12. 검사 항목(tests/run_tests.gd, 헤드리스)

이전 저장소의 방식대로 `check(cond, 설명)` 를 쌓고 마지막에 `RESULT: N checks passed, M failed` 를 출력합니다(종료 코드: 모두 통과 0, 하나라도 실패 1). 검사 함수는 끝에서 `done()` 을 부르므로 스크립트 오류로 중간에 끊긴 함수는 실패로 셉니다(검토 I33). 검사를 하나도 하지 않은 함수, 돌린 함수가 없는 실행, `--only` 의 모르는 이름(오타)도 실패입니다(검토 J15). `--skip-slow` 는 느린 검사(농사 도달·harsh_winter 멸종 틱)를 뺍니다. 검사 수와 결과는 TEST-REPORT.

**다시 잰 값(검토 고침 뒤, 2026-10-10):** 같은 명령(기본·씨앗 1·1,000세대)은 규칙 고침으로 역사가 바뀌어 112,234틱(세대당 약 112틱, 평균 개체 239 — 기록 줄의 90% 가 상한 250)이고, 이 날 기계에서 **733.8초(12.2분)** 였습니다. 같은 날 같은 기계에서 규칙 고침 전 코드도 같은 속도였으므로(개체·틱당 약 27~29µs) 늘어난 것은 코드가 아니라 기계 몫입니다(2단계 날보다 약 1.7배 느림 — 2단계 기계라면 7~8분으로 추정). **5분 목표는 여전히 못 맞춥니다.** 이 실행의 발견은 채집 1,665(23.0세대)·저장 2,208(30.6세대)·농사 3,779틱(56.6세대)으로, 2단계 실측(40.5·54.9·140.7세대)보다 훨씬 이릅니다(6절).

**화면:** 200마리 60FPS 는 실제 GPU 에서 미검증입니다(이 저장소의 측정은 가상 디스플레이의 소프트웨어 렌더링과 헤드리스 미세 측정 — TEST-REPORT 성능 절). 프레임 예산·실제 배속 표시는 그대로 정직하게 보입니다.

## 17. 2단계 구현 중 바뀐 것

자세한 근거와 측정은 [`TEST-REPORT.md`](TEST-REPORT.md) "1단계 2/5" 의 5절.
- 행동 고르기를 argmax → **확률적 정책**(`brain.policy = "sample"`, `(1 + softsign(o))^k`). 무작위 두뇌가 한 행동만 반복해 첫 세대가 멸종했기 때문. 유전체·저장 형식은 그대로.
- 짝 찾기 반경 `repro.mate_radius` 추가(기본 2). 저장 발견 집계는 채집 발견 뒤의 내려놓기만.
- 생태 기본값 조정(계절 2일·겨울 0.3, 한입 3, 대사 0.06, 성장 0.12, 번식 에너지 0.35·몫 0.3·쿨다운 10, 성숙 30, 최대 나이 200, 초기 200, 상한 250). 판단 간격은 1 유지.
