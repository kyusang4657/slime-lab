## 1. 지도·자원·시간

### 1.1 시간
- 시뮬레이션은 **틱** 단위로만 진행합니다. 1틱 = 모든 슬라임이 한 번 감지·판단·행동.
- 하루 `time.day_ticks`(기본 60) = 낮 `time.daylight_fraction`(0.6) + 밤. 빛 `light` 은 낮 1, 밤 0, 경계에서 `time.twilight_ticks` 동안 선형 변화(삼각함수 안 씀).
- 1년 = 계절 4개 × `time.season_days`(기본 2일). 계절 성장 배수 `seasons.growth = [1.0, 1.2, 0.8, 0.3]`(봄·여름·가을·겨울). `time.season_days = 0` 이면 계절 없음. (초안의 4일·겨울 0.1 은 겨울이 수명 한 번만큼 길어 첫 세대가 매번 멸종 → 17절. 혹독한 겨울은 예설정 `harsh_winter`)
- 화면 속도 1배 = `ui.speed.ticks_per_second_1x`(기본 6틱/초). 속도 1·2·4·8·16·32·64배와 **빨리 감기**(프레임 예산 안에서 최대한).

### 1.2 지도
- 격자 `map.width × map.height`(기본 64×48). 칸 종류: 풀밭(비옥도 0~1), 물(통과 불가), 바위(통과 불가, 식물 없음).
- 지형은 씨앗으로 생성: 정수 해시 기반 값 잡음(value noise) 2옥타브 → 비옥도, 별도 잡음 → 물·바위. 사칙연산만 씀.
- 생성 후 **BFS 연결성 검사**: 가장 큰 통과 가능 영역만 남기고 나머지 섬은 바위로 메움(슬라임이 갇히지 않게). 이전 저장소의 `grid_logic.gd` BFS 를 가져와 울타리·건물 점유 부분은 빼고 "통과 가능 칸·다중 출발 BFS 거리장"만 남깁니다.

### 1.3 식물(먹이)
- 풀밭 칸마다 먹이량 `food[c]`(0 ~ `plants.max_food × 비옥도 × resource_scale`).
- 매 틱 성장: `food += plants.regrow × 비옥도 × light_factor × season_growth × resource_scale` (상한까지). `light_factor` = 낮 1, 밤 `plants.night_growth`(기본 0).
- 사용자 파라미터 **자원량** = `resource_scale`(0~3, 기본 1). **0 이면 먹이가 생기지 않음 → 멸종**(검사 항목).
- 성능: 식물 갱신은 `plants.update_every`(기본 2)틱마다 몰아서, 감지용 **누적 합 표(summed-area table)** 를 같은 때 다시 만들어 슬라임의 영역 감지를 O(1)로 처리.

### 1.4 바닥에 놓인 먹이
- 운반하던 먹이를 내려놓으면 칸에 `dropped[c]` 로 쌓입니다. `dropped.spoil_ticks`(기본 90) 뒤 썩어 사라지고, 그때 풀밭이면 확률 `dropped.sprout_chance` 로 **싹이 틈**(그 칸 먹이 +`dropped.sprout_food`, 비옥도 +`dropped.sprout_fertility`). 이것이 농사 발견의 전조입니다(6절).

## 2. 슬라임

### 2.1 상태
| 필드 | 뜻 |
|---|---|
| id | 태어난 순서대로 증가(정렬·결정성 기준) |
| x, y, heading | 칸 좌표, 방향(북·동·남·서 4개) |
| energy | 0 ~ 최대 에너지(크기에 비례) |
| age | 틱 |
| carry | 운반 중인 먹이(채집 발견 후) |
| gen | 세대 |
| parent_a, parent_b | 부모 id(초기 개체는 -1) |
| genome | 신경망 가중치 + 특성 유전자(4절) |
| stats | 먹은 양·이동 수·자식 수 등(정보 창·통계용) |

한 칸에 여러 마리가 있어도 됩니다(충돌 해결 규칙이 필요 없어 결정성이 단순해짐). 화면에서는 칸 안에서 조금씩 비켜 그립니다.

### 2.2 특성 유전자(신경망 외)
| 유전자 | 범위 | 효과 |
|---|---|---|
| size | 0.6 ~ 1.6 | 최대 에너지 ×size, 기본 대사 ×size, 한입 크기 ×size |
| sense | 1 ~ 6 칸 | 감지 반경. 대사 비용 + `metab.sense_cost × sense` |
| hue | 0 ~ 1 | 색. 효과 없음(중립 표지 → 계통이 화면에서 색으로 보임), 느리게 변이 |

### 2.3 에너지
- 매 틱 소비 = `metab.base × size + metab.sense_cost × sense` (+ 이동하면 `metab.move × size`, 쉬기면 ×`metab.rest_factor`).
- 먹기 = 칸 먹이에서 min(`eat.bite × size`, 남은 먹이)를 가져와 × `eat.efficiency` 만큼 에너지로. 저장고 칸에서는 저장고 먹이를 먹음.
- 에너지 ≤ 0 → 굶어 죽음. age ≥ `life.max_age`(기본 200틱, 개체마다 ±`life.max_age_jitter`) → 늙어 죽음.
- **에너지 장부:** 세계 전체로 `먹은 양 × 효율 − 소비 − 자식에게 준 양 + ...` 가 매 틱 맞아떨어지는지 검사합니다(없는 데서 에너지가 생기지 않음).

### 2.4 번식(규칙 기반, D8)
- 조건: age ≥ `repro.maturity`(기본 30), energy ≥ `repro.min_energy_frac × 최대`(기본 0.35), 쿨다운(기본 10틱) 끝, 반경 `repro.mate_radius`(기본 2칸, 정사각형) 안에 같은 조건의 상대가 있음.
- 상대 고르기: 조건을 만족하는 반경 안 개체 중 id 가 가장 작은 개체(결정적). 한 틱에 한 번만 짝지음(id 오름차순으로 처리).
- 자식: 두 부모가 각자 `repro.cost_frac × 현재 에너지`를 내놓고, 그 합 × `repro.transfer_efficiency` 가 자식 에너지. 자식은 부모 a 칸에 태어남.
- 세계 개체 수 상한 `population.cap`(기본 250) 을 넘으면 번식하지 않음(폭주 방지·성능 보호).
- 선택 사항: `repro.asexual_when_alone = false`(기본 끔). 켜면 상대가 없을 때 에너지가 가득하면 분열.

## 3. 감지와 행동

### 3.1 입력(12개, 모두 대략 -1 ~ 1)
| # | 입력 | 계산 |
|---|---|---|
| 0 | 편향 | 1 |
| 1 | 에너지 | energy / 최대 |
| 2 | 발밑 먹이 | food[here] / max_food (저장고 칸이면 저장고 비율) |
| 3 | 앞쪽 먹이 | 앞 사분면(반경 sense) 먹이 합 / 정규화 (누적 합 표) |
| 4 | 왼쪽 먹이 | 왼 사분면 |
| 5 | 오른쪽 먹이 | 오른 사분면 |
| 6 | 붐빔 | 반경 2 안 개체 수 / `sense.crowd_norm` |
| 7 | 빛 | light (밤에는 감지 반경도 ×`sense.night_factor`) |
| 8 | 운반량 | carry / 최대 운반량(채집 전에는 항상 0) |
| 9 | 저장고 방향 | 가장 가까운 저장고로 가는 BFS 거리장 기울기와 heading 의 관계: 앞 1, 왼 -1, 오른 +1 쪽 기울기를 하나의 부호 값으로(-1 왼쪽 … +1 오른쪽, 0 없음/정면) |
| 10 | 저장고 가까움 | 1 / (1 + 거리) (없으면 0) |
| 11 | 계절 온기 | 현재 계절 성장 배수 / 최대 배수 |

### 3.2 출력(8개)과 행동 고르기
출력 0 앞으로, 1 왼쪽으로 돌기, 2 오른쪽으로 돌기, 3 먹기, 4 쉬기, 5 줍기(채집), 6 내려놓기, 7 심기.
- **확률적 정책(기본 `brain.policy = "sample"`)**: 출력 o 마다 z = softsign(o), 가중치 (1 + z)^k (k = `brain.sharpness`, 기본 4, 거듭 곱셈만 씀)에 비례하는 확률로 행동을 뽑습니다. 가중치가 크게 진화하면 거의 결정적이 됩니다. `"argmax"` 로 바꾸면 가장 큰 출력(같으면 번호가 작은 쪽). (초안은 argmax 였으나 무작위 두뇌가 거의 한 행동만 반복해 첫 세대가 멸종 → 17절)
- 여덟 행동은 언제나 고를 수 있습니다. 아직 발견되지 않은 행동(5·6·7)을 고르면 **"시도"** 로 기록만 하고 효과는 없습니다. 이 시도 통계가 발견의 재료입니다(6절). 단, 내려놓기는 처음부터 "가진 것이 없으면 효과 없음"이라 채집 전에는 자연히 시도만 됩니다.
- 판단 간격 `brain.think_every`(기본 1틱). 2 이상이면 그 사이 직전 행동을 반복합니다. (2 로 시험했더니 먹기·돌기 반복 낭비로 첫 세대가 멸종해 1 로 둠 → 17절)

## 4. 두뇌(D1 — 확정: A)

### 4.1 권장안: 고정 구조 앞먹임 신경망
```
입력 12 ──(12×8 가중치)──▶ 은닉 8 (softsign: x / (1 + |x|)) ──(8×8 가중치)──▶ 출력 8 (선형, 가장 큰 값 선택)
```
- 가중치 160개 + 특성 유전자 3개 = **유전체 163개 실수**.
- **softsign** 은 사칙연산만 쓰므로 Windows·Linux·macOS 에서 비트 단위로 같은 결과(tanh·exp 는 C 라이브러리마다 마지막 비트가 다를 수 있음).
- 가중치는 **float32 로 저장**(PackedFloat32Array), 계산은 float64. 태어날 때 float32 로 반올림해 두므로 저장·복원이 비트 단위로 정확합니다.
- **교차:** 뉴런 단위 — 은닉 뉴런 j 의 들어오는 가중치 12개와 나가는 가중치 8개를 한 덩어리로 보고, 덩어리마다 부모 a·b 중 하나를 고름(무작위 0.5). 특성 유전자는 각각 고름. 같은 역할 뉴런이 함께 움직여 "평균하면 망가지는" 문제를 줄입니다.
- **돌연변이:** 유전자마다 확률 `mutation.rate`(사용자 파라미터, 기본 0.05)로 + N(0, `mutation.sigma`)(기본 0.3), 가중치는 ±`brain.weight_clamp`(기본 4)로 자름. N(0,1)은 균등 난수 4개 합(어윈-홀) 근사 — log·cos 를 쓰지 않기 위해.
- 초기 개체: 가중치 균등 [-`brain.init_range`, +]. 처음 세대가 살아남도록 시작 먹이를 넉넉히(`plants.initial_fill`) 채웁니다.

### 4.2 다른 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 고정 앞먹임 12-8-8 (권장)** | 빠름(곱셈 160회/판단), 유전체 길이 고정 → 저장·교차·분석 단순, C# 이식 쉬움 | 기억이 없음(지금 감지만 보고 판단) |
| B. A + 기억 뉴런 2개(출력 2개를 다음 틱 입력으로 되먹임) | 겨울 대비·왕복(먹이↔저장고) 같은 시간 행동을 배울 여지 | 입력 14·출력 10 → 가중치 약 200개, 진화가 느려질 수 있음, 해석이 어려움 |
| C. NEAT(구조까지 진화) | 표현력·연구 재미 | 구현·검사 비용 큼, 유전체 길이 가변 → 저장·교차·성능 모두 복잡, 200마리 60FPS 위험 |

**권장 이유:** 1단계 목표(결정성·1,000세대 속도·저장 왕복)를 가장 안전하게 맞춥니다. B 는 config 의 `brain.memory_units` 를 0→2 로 바꾸는 것만으로 켜지게 설계해 두어(입력·출력 배열 길이를 config 에서 계산), 나중에 실험 변수로 쓸 수 있게 하겠습니다. 스냅숏에는 `brain` 설정(입력·은닉·출력·기억 수)이 함께 저장되므로, 기억을 켠 실험과 끈 실험은 각자 스냅숏을 정확히 복원하고 서로 섞이지만 않습니다(유전체 길이가 다르면 불러오기에서 거부).

**확정(2026-10-07):** A 로 시작하고, B 는 같은 코드에서 `brain.memory_units = 2` 로 켜는 **실험 변수**로 둡니다. 1단계 검사는 기억 0 과 2 두 경우 모두 순전파·교차·왕복을 확인합니다.

## 5. 상속과 진화 요약
- 유전체 = 가중치 + size·sense·hue. 교차(4.1) → 돌연변이 → float32 반올림 → 범위 자르기.
- 평생 학습은 없습니다(D3). 개체가 겪은 것은 유전되지 않고, 세계의 **발견**만 누적됩니다.
- 계통 기록: 모든 개체의 (id, 부모, 세대, 태어난 틱, 죽은 틱, 죽은 이유, 자식 수, 특성)을 남깁니다. 화면의 가계도와 lineage.csv 의 원천.

## 6. 발견과 건물(규칙 기반 문명 층)

발견은 **세계 전체**가 공유하고(D5), 순서는 채집 → 저장 → 농사로 고정입니다(앞 단계가 열려야 다음 통계를 셈).

| 단계 | 재료 통계(셈 조건) | 임계(config) | 열리는 것 |
|---|---|---|---|
| 1 채집 | "배부른 줍기 시도": 에너지 ≥ `discovery.forage_min_energy_frac` 이고 먹이 칸에서 줍기(5)를 고른 횟수, 누적 | `discovery.forage_threshold`(기본 300) | 줍기: 칸 먹이를 운반(최대 `carry.max × size`). 운반 중 쉬기·먹기 시 운반분을 먹을 수 있음. 내려놓기: 칸에 `dropped` 로 놓음 |
| 2 저장 | "모아 놓기": (채집 발견 뒤) 내려놓은 먹이 양을 `discovery.region_size`(8)칸 구역마다 누적. 어느 구역이든 | `discovery.store_threshold`(기본 60) | **저장고** 건설: 그 구역에서 가장 많이 놓인 칸(같으면 번호 작은 칸)에 저장고 1개. 저장고 칸에 내려놓으면 저장(썩지 않음, 용량 `store.capacity`), 저장고 칸에서 먹으면 저장분을 먹음 |
| 3 농사 | "저장고 근처 싹": 저장고 반경 `discovery.farm_radius` 안에서 썩은 먹이가 싹튼 횟수, 누적 | `discovery.farm_threshold`(기본 15) | 심기: 운반 먹이 1을 써서 앞 칸(풀밭, 저장고 반경 `farm.radius` 안)을 **밭**으로. 밭은 비옥도 1, 성장 ×`farm.growth_mult`, 최대 ×`farm.max_mult`, 겨울 성장 하한 `farm.winter_floor` |

**건물 2종**
| 건물 | 크기 | 생기는 방법 | 규칙 |
|---|---|---|---|
| 저장고 | 1칸(통과 가능) | 저장 발견 시 1개. 이후 기존 저장고에서 `store.min_spacing` 밖의 구역에 내려놓기가 다시 임계를 넘으면 추가(최대 `store.max_count`) | 용량 `store.capacity`. 저장분은 썩지 않음. 거리장(BFS)을 다시 계산해 입력 9·10 갱신 |
| 밭 | 1칸 | 심기 행동 | 밭이 `farm.abandon_ticks` 동안 아무도 밟지 않으면 풀밭으로 돌아감(버려진 마을이 보이게) |

- 발견 순간은 연대기에 "t=12,340 (평균 37.2세대) **채집 발견** — 마지막 시도자 #4,511" 처럼 기록하고 화면에 알림·합성 종소리.
- 발견 후 압력: 채집·저장이 열리면 겨울을 버티는 계통이 유리해져 행동이 진화로 강화되는지가 관찰 대상입니다. 이것이 연구 질문이며, 결과가 어떻게 나오든 그대로 보고합니다.
- 임계가 너무 낮으면 "우연한 행동만으로" 문명이 열립니다. 기본값은 첫 측정 후 조정하고 그 근거를 TEST-REPORT 의 수치 변경 기록에 남깁니다.

## 7. 결정성(D10)

- **같은 씨앗 + 같은 파라미터 + 같은 실행 파일 = 같은 역사.** 비트 단위로 같아야 하며 매 실행 끝에 **역사 해시**를 냅니다.
- 난수: Godot `RandomNumberGenerator`(PCG32, 정수 기반)의 `randi`/`randf` 만 사용, `randfn` 금지. 용도별로 흐름을 나눔: `rng_world`(지형·식물·싹), `rng_life`(교차·돌연변이·수명 흔들림). 상태(`state`)는 스냅숏에 저장.
- 처리 순서: 모든 반복은 id 오름차순 또는 칸 번호 오름차순. Dictionary 순회 결과에 의존하지 않음. 출생은 틱 끝에 일괄 추가, 사망은 틱 끝에 일괄 제거(순서 보존 압축).
- 수학: 시뮬레이션 코드(scripts/sim)에서 `sin cos tan exp log pow` 사용 금지 — 검사가 소스를 훑어 확인(7.1).
- 역사 해시: 매 `hash.every`(기본 100)틱마다 (틱, 개체 수, 에너지 합의 float64 비트, id 합, 발견 단계, 먹이 합 비트)를 이어 붙여 해시. 마지막 값을 summary.json 에 기록.
- **플랫폼 간:** CI 는 Linux 에서 검사합니다. Windows·macOS 에서 같은 해시가 나오는지는 설계상 기대하지만 1단계에서는 **미검증**으로 보고합니다(Windows 빌드 산출물로 수동 확인 절차만 문서화).

### 7.1 매직 넘버 금지 검사
`scripts/sim/*.gd` 에서 0, 1, -1, 2, 0.0, 1.0, 0.5 와 배열 첨자 외의 숫자 상수를 찾아 실패시키는 정적 검사를 둡니다(허용 목록은 검사 파일 안에 명시). 모든 수치는 `config/sim-defaults.json` 에서 읽습니다.

## 8. 데이터 구조와 형식(D2 — 확정: A)

### 8.1 시뮬레이션 내부(구조 배열, SoA)
슬라임은 객체가 아니라 필드별 Packed 배열입니다(`PackedInt32Array ids, xs, ys, headings, ages, gens...`, `PackedFloat64Array energy...`, 유전체는 `PackedFloat32Array` 하나에 개체 × 163 칸). GDScript 에서 객체보다 빠르고, 나중에 C#/GDExtension 으로 옮길 때 그대로 배열 경계가 됩니다.

### 8.2 설정
- `config/sim-defaults.json` — 시뮬레이션 수치 전부(단일 기준). 최상위 키: `map, time, seasons, plants, dropped, metab, eat, life, repro, population, sense, brain, mutation, carry, store, farm, discovery, hash`.
- `config/presets.json` — 실험 예설정(이름 → 덮어쓸 값). 예: `default`, `abundant`, `harsh_winter`, `fast_civ`, `no_resources`.
- `config/ui.json` — 화면 수치(색·속도 단계·그래프 표본 간격·카메라).
- 실험 = 기본값 + 예설정 + 사용자 덮어쓰기(파라미터 패널·명령줄). 결과 폴더에 **실제로 쓴 전체 설정**을 함께 저장합니다.

### 8.3 스냅숏(저장·복원) — 권장안
```json
{
  "format": "slime-lab-snapshot", "version": 1,
  "app_version": "0.1.0", "seed": 42, "tick": 12000,
  "config": { ...실제 쓴 전체 설정... },
  "rng": { "world": "<state int 문자열>", "life": "..." },
  "world": { "food_b64": "...", "dropped_b64": "...", "fertility_b64": "...", "tiles_b64": "..." },
  "slimes": { "count": 183, "id": [...], "x": [...], ..., "energy": [...], "genome_b64": "<float32 LE>" },
  "civ": { "stage": 2, "counters": {...}, "buildings": [...] },
  "lineage_b64": "...", "chronicle": [...], "history_hash": "..."
}
```
- **실수는 JSON 숫자로 저장하지 않습니다.** Godot 4.4.1 의 `JSON.stringify(..., full_precision = true)` 가 0.1+0.2 를 `0.3` 으로, 1e-300 을 `0` 으로 써서 비트 왕복이 안 되는 것을 구현 중 확인했습니다. 배열은 base64(리틀엔디언), 단일 실수(장부 등)는 float64 비트 16진 문자열로 둡니다. 설정은 사람이 읽도록 JSON 숫자로 두되, `SimConfig.validate` 가 "JSON 으로 글자 왕복해도 같은 값"인지 검사해 유효숫자 15자리를 넘는 값을 거부합니다.
- 64비트 정수(난수 상태)는 JSON 실수 정밀도를 넘으므로 **문자열**로.
- 저장은 이전 `save_manager.gd` 방식(임시 파일 → 검증 → 교체, 직전 정상본 `.bak`, 깨진 파일 `.broken` 보존)을 그대로 씁니다. 불러올 때 버전·배열 길이·범위·유전체 길이(= 설정에서 계산한 길이)를 검사합니다.

### 8.4 실험 결과 폴더(헤드리스·화면 공통)
| 파일 | 내용 |
|---|---|
| `summary.json` | 씨앗, 설정, 끝난 이유(세대 도달·멸종·틱 상한), 틱 수, 최종 평균 세대, 발견 시각, 역사 해시, 실행 시간 |
| `timeseries.csv` | `record.every`(기본 20)틱마다 한 줄: `tick,day,season,light,population,births,deaths,mean_gen,mean_energy,mean_size,mean_sense,mean_age,food_total,dropped_total,stored_total,carry_total,civ_stage,storehouses,farms,forage_attempts,store_drops,farm_sprouts` |
| `chronicle.csv` | `tick,mean_gen,kind,actor_id,text` (발견·멸종·최대 인구·건물 생김 등) |
| `lineage.csv` | `id,parent_a,parent_b,gen,birth_tick,death_tick,death_cause,children,size,sense,hue` (`--no-lineage` 로 끔) |
| `final.snapshot.json` | 마지막 상태(8.3) — 이어서 돌리거나 화면에서 열기 |

- CSV: UTF-8(BOM 없음), 쉼표, 영문 snake_case 열 이름(pandas·R·스프레드시트 바로 읽기), 소수점은 `.`. 화면의 글자는 한국어.

### 8.5 다른 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. JSON + base64 이진 배열 (권장)** | 메타는 사람이 읽음, 부피 작음(200마리 유전체 약 130KB), 정확한 왕복, 엔진 독립(C#·파이썬에서 읽기 쉬움) | 배열 부분은 눈으로 못 읽음 |
| B. 전부 JSON 숫자 | 완전히 사람이 읽음 | 크기 3~5배, 실수 왕복에 full_precision 필수 |
| C. Godot `var_to_bytes`/리소스 | 구현 가장 짧음 | Godot 전용·버전 의존, C# 이식·외부 분석에 불리 |

## 9. 시뮬레이션과 화면 분리

```
scripts/sim/   (Node 없음, RefCounted 만, 렌더링·입력·파일 대화상자 없음)
  sim_config.gd    설정 로드·병합·검증 (이전 game_config.gd 방식)
  rng.gd           PCG32 감싸기, 어윈-홀 정규 근사, 상태 저장
  grid.gd          통과 가능 칸, 이웃, 다중 출발 BFS 거리장 (이전 grid_logic.gd 에서 가져옴)
  terrain.gd       정수 해시 값 잡음, 연결성 정리
  brain.gd         순전파, 교차, 돌연변이 (정적 함수, 배열 입출력)
  world.gd         SimWorld: step(n), 감지·행동·번식·사망·식물·발견 순서
  civ.gd           발견 통계와 건물
  recorder.gd      시계열·연대기·계통 → CSV/JSON
  snapshot.gd      to_dict / from_dict / validate, 저장 관리
scripts/view/  3D 지도 (sim 을 읽기만 함)
scripts/ui/    실험실 화면
```
- 화면은 `SimWorld` 의 **읽기 전용 질의**(`slime_count()`, `slime_pos(i)`, `slime_info(id)`, `tile_food(c)`, `buildings()`, `drain_events()`)와 `step(n)` 만 씁니다. 같은 질의를 갖는 C# 구현으로 바꿔 끼울 수 있도록 이 목록을 `docs/SIM-API.md` 로 고정합니다.
- 한 틱 순서: ① 빛·계절 계산 ② (필요 시) 식물 성장·누적 합 표 ③ 슬라임마다(id 오름차순) 감지 → 판단 → 행동 → 대사 ④ 번식 짝짓기(id 오름차순) ⑤ 사망 처리 ⑥ 바닥 먹이 썩음·싹 ⑦ 발견 판정·건물 ⑧ 기록·해시.

## 10. 화면 구성(실험실)

1920×1080 기준(최소 1280×720), PC 마우스·키보드.

```
┌──────────────┬───────────────────────────────────────────┬──────────────┐
│ 파라미터 패널 │              지도 관찰 창(3D)              │  개체 정보    │
│ 예설정 ▾      │   ▶ ‖ 1 2 4 8 16 32 64 ⏩  t=12,340 37.2세대 │  #4511 3대   │
│ 씨앗 [42]     │                                           │  에너지 ▇▇▇░  │
│ 돌연변이율 ─● │                                           │  나이·특성    │
│ 자원량   ──●  │                                           │  두뇌 그림    │
│ 초기 개체 ─●  │                                           │  가계도(2대)  │
│ [새 실험]     │                                           │  [따라가기]   │
│ [비교 모드]   │                                           │              │
│ [저장][열기]  │                                           │              │
│ [CSV 내보내기]│                                           │              │
├──────────────┴───────────────┬───────────────────────────┴──────────────┤
│ 그래프: 개체수 │ 평균 특성 │ 기술 단계                │ 연대기(최신 위)       │
└──────────────────────────────┴──────────────────────────────────────────┘
```
- **지도 관찰 창:** 비스듬한 위 3D. 끌기 = 이동, 휠 = 확대, 오른쪽 끌기 = 회전. 땅은 칸마다 정점 색(비옥도·먹이량, 밤에는 어둡게) 메시 하나, 식물은 MultiMesh(먹이량에 따라 크기), 슬라임은 **조각 구 메시 하나를 MultiMesh 로**(200마리 = 그리기 호출 1). 개체별 색(hue), 크기(size), 통통 튀는 눌림(틱 사이 보간), 운반 중이면 머리 위 열매.
- **슬라임 모델:** 이전 `demon_geo.gd` 의 `sculpt()`(방향별 반지름 함수로 구 변형)를 가져와 아래가 납작하고 위가 둥근 물방울형, 두 눈은 같은 메시의 정점 색. 표정·뼈대 없음(MultiMesh 이므로). 삼각형 예산 `ui.slime.triangles_max`(기본 400).
- **건물:** 저장고 = `lathe()` 회전체(둥근 움집 + 뚜껑), 밭 = 칸 위 이랑 줄무늬 판. 코드로 생성.
- **클릭:** 땅과 광선 교차 → 그 칸 근처 가장 가까운 슬라임 선택 → 오른쪽 정보 창(상태·특성·현재 행동·두뇌 가중치 열지도·부모·조부모·자식 목록, 이름 대신 #id와 색 점). 가계 항목을 누르면 그 개체(살아 있으면 지도에서, 죽었으면 기록)로 이동.
- **파라미터 패널:** 돌연변이율·자원량·초기 개체 수·씨앗(+ 예설정). 바꾸면 **새 실험**을 눌러야 적용(진행 중 실험의 조건이 섞이지 않게). 고급 설정은 접어 두고 config 키 이름 그대로 표시.
- **속도:** 1~64배와 빨리 감기. 시뮬레이션은 프레임당 시간 예산(`ui.speed.sim_budget_ms`, 기본 10ms) 안에서만 돌리고, 따라가지 못하면 "목표 64배 / 실제 23배" 로 정직하게 표시.
- **그래프 3개:** 직접 그리는 Control(`_draw`). ① 개체 수(+출생·사망) ② 평균 특성(size·sense·평균 세대 중 선택) ③ 기술 단계 계단선 + 저장고·밭 수 + 발견 표시. 가로축은 틱/세대 전환.
- **연대기:** 발견·멸종 위기(최저 인구)·최대 인구·우세 계통 교체·건물 생김. 줄을 누르면 그 시점 표시.
- **CSV 내보내기:** 8.4 와 같은 폴더 구성을 사용자가 고른 폴더(기본 `user://experiments/<시각>-seed<N>/`)에 씀.
- **비교 모드:** 실험 A·B 를 각자 설정으로 만들어 지도 창 둘을 나란히(SubViewport 2개), 같은 속도로 번갈아 진행. 그래프는 한 축에 A 실선·B 점선으로 겹침. 연대기는 A/B 표시.
- **소리:** 발견 종소리·멸종 낮은 음 2종만, 실행 중 파형 합성(AudioStreamWAV). 메뉴에서 끄기. 글꼴은 나눔고딕 보통·굵게(`assets/fonts/NanumGothic-*.ttf`, NHN Corporation, SIL OFL 1.1 — 전문 `assets/fonts/OFL-NanumGothic.txt`)를 프로젝트 기본 글꼴로 쓰고 CREDITS 에 기록(3단계에서 바꿈, 18절).

## 11. 헤드리스 실행기

```
godot --headless --path . --script res://tests/run_experiment.gd -- \
    --seed=42 --generations=1000 --out=results/seed42 \
    [--preset=default] [--set=mutation.rate=0.08 --set=plants.regrow=0.3] \
    [--max-ticks=2000000] [--no-lineage] [--snapshot-every=10000] [--resume=path/to/snapshot.json]
```
- 끝나는 조건: 평균 세대 ≥ N, 멸종, `--max-ticks`. 끝난 이유를 summary 와 마지막 줄에 표시:
  `RESULT: seed=42 generations=1000.0 ticks=81230 pop=187 civ=3(농사) hash=9f3c… time=212.4s reason=generations`
- 진행 표시는 10초마다 한 줄(틱/초 포함). 종료 코드: 정상 0, 인자·설정 오류 2.
- `--resume` 은 스냅숏에서 이어 돌리며, 끊김 없이 돌린 것과 같은 해시가 나와야 합니다(검사).

## 12. 검사 항목(tests/run_tests.gd, 헤드리스)

이전 저장소의 방식대로 `check(cond, 설명)` 를 쌓고 마지막에 `RESULT: N checks passed, M failed` 를 출력합니다. 테스트 함수가 끝까지 실행되지 않으면 실패로 셉니다.

| 묶음 | 확인 내용 |
|---|---|
| 설정 | 모든 키 존재·범위, 예설정 병합, 알 수 없는 키 거부, 매직 넘버 정적 검사(7.1), 금지 수학 함수 정적 검사 |
| 난수 | 같은 씨앗 같은 수열, 상태 저장·복원 후 같은 수열, 정규 근사 평균·분산 |
| 지형 | 씨앗별 결정적, 통과 가능 영역 하나로 연결, 물·바위 비율 범위 |
| 두뇌 | 알려진 가중치로 순전파 값, 동률 시 작은 번호, 돌연변이율 0 → 자식 = 부모 덩어리 그대로, 교차가 뉴런 덩어리를 깨지 않음, float32 반올림, 가중치 범위 |
| 생태 | 밤 성장 0, 자원량 0 → 먹이 0, 에너지 장부 맞음, 굶주림·노화 사망, 번식 조건·에너지 전달, 개체 수 상한 |
| 발견 | 각 단계 임계에서 정확히 한 번, 순서 강제(앞 단계 없이 안 열림), 저장고 위치 규칙, 저장분 썩지 않음, 심기 → 밭, 버려진 밭 복귀, 발견 전 행동은 효과 없음 |
| **결정성** | 같은 씨앗 2회 실행 → 같은 역사 해시·같은 timeseries.csv, 다른 씨앗 → 다른 해시 |
| **농사 도달** | `presets.json` 의 예설정 중 **적어도 하나가 평균 100세대 안에 농사(3단계)에 도달**. 어느 예설정·어느 씨앗인지 출력 |
| **멸종** | 자원량 0 → `life.max_age` + 여유 틱 안에 개체 0, 끝난 이유 = 멸종 |
| **저장·복원 왕복** | 틱 T 에서 스냅숏 → JSON 문자열 → 복원 → 다시 직렬화가 같은 문자열, 그리고 T+K 까지 이어 돌린 해시 = 끊김 없이 돌린 해시. 깨진 파일 → 백업 복구, 길이 틀린 유전체 거부 |
| 실행기 | run_experiment 출력 파일 존재·열 이름·행 수, 인자 오류 코드 |
| 성능(기록) | 200마리 1,000틱 헤드리스 틱/초를 출력(실패 기준은 목표의 절반 미만일 때만, CI 기계 차이 감안) |

**화면 검사**(가상 디스플레이, `tests/ui_driver.gd`): 실험실 장면 열기 → 진행 → 슬라임 클릭 → 정보 창 내용 → 속도 64배 → CSV 내보내기 → 비교 모드 → 각 단계 캡처를 `docs/screenshots/v0.1/` 에. 결과 `RESULT: N passed, M failed (ui)`.

**추정(초안):** 세대 시간 ≈ 성숙 40 + 짝 찾기·쿨다운 ≈ 60~80틱 → 1,000세대 ≈ 7만 틱 × 150마리 ≈ 1,000만 개체·틱. ## 17. 2단계 구현 중 바뀐 것

- 스냅숏의 단일 실수는 비트 16진 문자열(Godot JSON 실수 정밀도 문제).
- 기본값에서 농사 도달은 씨앗에 따라 평균 35~172세대(씨앗 1~4 조사), 예설정 `fast_civ` 는 약 20세대(2단계 당시). 4단계에서 `fast_civ` 를 다시 맞춤: 씨앗 1~12 농사 중앙값 15.9세대(1.98~74.3, 12/12 — [`TUNING-fast_civ.md`](TUNING-fast_civ.md)), 예전 값은 시연용 `demo_fast`(약 2세대)로 남김.

- **멀리서 보기:** 전경에서 슬라임이 몇 픽셀로 작아지지 않게 화면 최소 크기만큼 키워 그림(시뮬레이션과 무관한 표시 배율), 선택 고리도 화면 최소 크기. 큰 지도도 처음에 다 보이게 카메라 최대 거리를 맞춘 거리에 따라 늘림. Home = 전체 보기.
- **속도 표시:** 실제 배속은 틱의 소수 몫까지 세고(따라가면 정확히 목표 배속), 잘리지 않은 프레임 시간으로 재며, 배속·멈춤·빨리 감기를 바꾸면 창을 비움. 시뮬레이션 예산은 다음 틱 비용을 미리 더해 보고 넘기 전에 멈춤.
- **멸종:** 그 순간 멈추고(`lab.pause_on_extinction`, 헤드리스 실행기의 끝 조건과 같게) 멸종 표지를 계속 보임.
- **시뮬레이션 쪽 작은 변경(결과·해시 그대로):** 빛·계절을 `step()` 끝에서도 다시 계산해 틱 사이의 `light`·`season` 이 지금 틱을 뜻하게(기록 CSV 의 경계 줄이 한 틱 앞당겨짐), `drain_events()` 는 연대기와 따로인 사본.
- **분석 도구:** 14절의 `montage.py` 대신 `tools/analyze.py`(씨앗 묶음·파라미터 격자 → 표·보고서·그림, [`ANALYSIS.md`](ANALYSIS.md)).

## 19. 4단계 구현 중 바뀐 것

자세한 계약은 [`VIEW-API.md`](VIEW-API.md) "4단계 계약", 검사·측정은 [`TEST-REPORT.md`](TEST-REPORT.md) 4단계 절.
- **실험 = 세계 + 기록기(`Experiment`):** 화면도 헤드리스 실행기와 같은 줄을 기록한다(만들 때 한 줄, `record.every` 마다 한 줄). 그래서 화면의 "CSV 내보내기" 결과가 같은 씨앗·설정·틱 수의 실행기 결과와 글자까지 같다. 그래프·연대기는 이 기록과 `world.chronicle` 만 읽고, 시뮬레이션은 LabMain 만 진행한다.
- **배치(10절 그림에서 바뀜):** 정보 창이 아래 자리 옆까지 세로 전체를 쓰고(두뇌 열지도가 1600×900 에서 스크롤 없이 — V07), 아래 자리(그래프 + 연대기)는 왼쪽 자리 + 지도 폭. 위쪽 막대에는 1280 폭에 여유가 없어 자리 접기 단추를 지도 오른쪽 아래에 둠. 연대기 폭은 창이 좁으면 줄어듦(1600 창 420px, 1280 창 331px — 고정 420 이면 1280 창에서 정보 창이 46px 밖으로 밀렸음).
- **비교 모드:** 두 세계는 틱마다 A 다음 B 로 진행해 언제나 같은 틱, 시뮬레이션 예산은 둘 몫을 합쳐 셈. 한쪽만 멸종하면 멈추지 않고(살아남은 쪽을 같은 틱으로 계속 견줌), 모두 멸종하면 멈춤. 위쪽 막대는 평균 세대 대신 A·B 개체 수·문명(평균 세대는 그래프에서).
- **그래프:** "보조 축"(저장고·밭 수)을 이중 축 대신 기술 단계 아래 작은 띠 둘로(눈금이 다른 두 수를 한 그림에 겹치면 거짓 상관이 보임). A·B 계열 색을 색각 이상 검사를 통과하는 #2aa98a·#d97630 으로 바꿈(3단계 기본값은 강조색과 같고 명도·채도 범위 밖). 개체가 0 인 줄의 평균값은 NaN(선이 끊김, 거짓 0 없음). 줄이 많아도 픽셀 열마다 첫·최소·최대·끝 줄만 그림.
- **파라미터 패널:** 패널 값 = 다음 실험 조건(진행 중 실험에 섞이지 않음). 강조·"바꾼 값 N개" 는 예설정이 아니라 **지금 실험**과 견줌. 검사는 `SimConfig.build` 그대로 + 초기 개체 수 ≤ 상한 하나. 스냅숏을 열면 다른 값이 가장 적은 예설정 + 다른 값으로 칸을 맞춰, "새 실험" 이 그 조건·씨앗을 0틱부터 다시 돈다.
- **연대기:** 한글 줄바꿈을 낱말(빈칸) 단위로 직접 접음(Godot 의 ICU 줄바꿈은 음절 사이 "남/은" 에서 끊음). 다른 Label 은 공용 `UiTheme.keep_words`(낱말 잇개 U+2060, 폭 0)로 같은 효과. 보이는 줄만 그리는 Control 하나(300줄이어도 노드 9개).
- **소리(10절 "2종" → 3종):** 발견 차임·멸종 낮은 음 + 저장고 "톡". 사인 + 약한 배음, 16비트 모노 22050Hz 를 실행 중 합성(CC0), 같은 소리는 0.5초에 한 번, 한 번에 온 사건 묶음은 가장 중요한 소리 하나만.
- **사용자 데이터 폴더:** 프로젝트 이름이 한글이라 `user://` 실제 경로에 한글이 들어가면 Godot 4.4 의 엔진 FileDialog 가 거짓 "권한 없음" 을 띄워, `application/config/custom_user_dir_name = "slime-lab"`(영문)으로 바꿈.
